## C1: CONNECTIONS  
**Goal**: Activate prior knowledge and connect to what learners already know

### What Learners Already Know
- **Traditional OOP**: Classes, inheritance, interfaces, mutable state, methods with side effects
- **SOLID Principles**: SRP, OCP, LSP, ISP, DIP
- **C# Basics**: Properties, methods, constructors
- **Limited FP Exposure**: May have used LINQ but not deep functional programming concepts

--

## C2: CONTEXT - phase 1

###  SOLID → CUPID 
- 🔧 Single Responsibility → **Unix Philosophy**
- 🏠 Open/Closed → **Composable**
- 🚀 **Domain-based**: Types model domain concepts clearly

--

## 🛠️ C3:  PRACTICE - phase 1
**Goal**: respect the Harness Rules
  - HA5: no god class (max 6 public properties)
  - HA6: single concern (public methods span at most one bounded-context concern)
  - HA7: fan-out (an entity references at most 3 entity types)
  - HA8: no persistence in the domain (no EF/ORM attributes or sync/hydrate shadows)
  - HA11: records are value objects
  - HA12: rich identifiers (not a bare Guid/Empty)


--

## C2: CONTEXT - phase2

###   →  complete CUPID

- 🔮 Complex Syntax (if, throw) → **Predictable** → **ADT**
- 🆔 OO Syntax → **FP Idiomatic**

--


## C2: CONTEXT - phase2

###  OOP → more Functional Programming
- ƛ Single function → **Either-ish monad** (OneOf)
- 🔒 Mutable state → **Immutable data**
- 🎯 Imperative → **Pattern matching**
- ✨ Object methods → **Pure functions**

--

## 🛠️ C3:  PRACTICE - phase 2

**Goal**: respect the other Harness Rules

- HA1: C# idioms
- HA2: immutable data (records, no setters, no mutable collections)
- HA4: composable no inheritance,
    - no throwing constructors, 
    - a OneOf property on Product, 
    - validating factories, 
    - Match instead of is/as/switch, 
    - no clock in the model

    
--

### **Goal**: Reflection & integration

- **Learning Harvest**: What surprised you? What resonates?
- **Before/After Comparison**: What improved most?
- **Action Plan**: Tomorrow, this week, this month
